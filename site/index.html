PortFlow · Terminal IT operations case study

From a business problem to a supported change, in one terminal integration

A vehicle terminal in Zeebrugge receives vehicle announcements from logistics partners over REST and EDI. Bad data used to surface at the gate. This case follows the work of an IT Development Officer: requirements, specification, integration, Oracle, testing, release, and the incidents and changes once it runs.

Fictional case built as a portfolio. Terminal, partners, figures and incidents are invented.

The case in eight stops

  1. 01Business requirement

    Problem, rules, stories, FR/NFR with IDs.

  2. 02Architecture

    Why each component exists; demo vs JBoss/Oracle/iWay.

  3. 03API and EDI flow

    One canonical model, idempotent, no lost messages.

  4. 04Oracle queries

    Support investigations with data; run in CI on Oracle.

  5. 05Incident investigation

    Outside-in analysis, real logs, five whys.

  6. 06Change request

    Scope, impact, security, risk, approval.

  7. 07Test plan

    Given / When / Then, each linked to an automated test.

  8. 08Release and rollback

    Checklist, smoke test, rollback criteria.
